XGBOOST, LIGHTGBM, CATBOOST AND THEIR ANCESTORS

Boosting five ways

All five build a team of small decision trees, one at a time, where each new tree works on what the team still gets wrong. They differ in how they find those mistakes and how they build each tree.

The idea they share

A single tree is a weak predictor. A boosted model starts with a simple guess, then adds small corrections. The final score for a customer is the starting guess plus what every tree adds or subtracts.

One customer's default score, with made-up numbers. Trees that raise it are raspberry, and trees that lower it are teal.

What each one changed

  1. 1995AdaBoostGive missed rows more weight, then let the trees vote.
  2. 2001Gradient boostingFit each new tree directly to the remaining errors. Works with many loss functions.
  3. 2014XGBoostAdd curvature to the math and put penalties inside the split decision.
  4. 2017LightGBMGroup values into bins for speed and split the most useful leaf first.
  5. 2017CatBoostUse categories without leaking the answer, and build symmetric trees.

ADABOOST / 1995

AdaBoost

Make the next tree care more about the rows the last one missed.

Imagine a class studying for an exam in turns. Each student gets a question list where the questions the previous student missed are printed larger. At the end they vote, and students who did better get a louder vote.

  1. Give every row the same weight, then fit a stump: a tree with one question.
  2. Give the stump a “say” based on its weighted error. Lower error means more say.
  3. Raise the weight of the rows it got wrong, lower the rest, and fit the next stump.
  4. The final prediction is a weighted vote of all the stumps.

GRADIENT BOOSTING / 2001

Gradient boosting

Fit each new tree to whatever error is left.

Think of golf. The first shot gets you close. Each later shot aims at the distance that remains, not at the original hole position from the tee. Each tree is one shot, and the learning rate is how hard you swing.

  1. Start with a simple guess, such as the average.
  2. For each row, calculate the error that's left.
  3. Fit a small tree to those errors, not to the original target.
  4. Add a fraction of that tree to the model (the learning rate), then repeat.

This lab uses regression because you can see the errors directly. For default prediction the model works in log-odds and the “error” is y − p, the actual outcome minus the predicted probability. That's the negative slope of the log loss, which gives the method its name.

Good atFlexible modelling with any differentiable loss. It's the foundation of the next three.

Watch outClassic implementations check every split point, so they slow down on big data. Too many trees or a high learning rate will overfit.

XGBOOST / 2014

XGBoost

Use the slope and the curvature, and charge a fee for complexity.

Same golfer, with two upgrades. They now read how the green curves before choosing how hard to hit. And a referee charges a fee for every extra split, so a split has to earn its place. XGBoost also engineered this to run fast, with parallel training and built-in handling of missing values.

Upgrade 1: curvature tells you how far to step

Where you are now Fixed step using slope only Step using slope and curvature

Both starting points have the same slope, so slope alone treats them the same. Curvature shows that one bowl is narrow and the other is wide. Classic gradient boosting picks its splits from the slope alone, though it may refine leaf values afterward. XGBoost uses slope and curvature for both.

Upgrade 2: penalties inside the split decision

Suppose the model currently predicts a 20% default rate for all 44 customers in this node. Should it split them? The left group is large with few defaults. The right group is tiny with mostly defaults.

Solid bar: leaf's push on the score at this λPale bar: its push with no penalty (λ = 0)
Gain from this split, with the fee marked in orange

leaf weight = −G / (H + λ) gain = ½ [ G_L²/(H_L+λ) + G_R²/(H_R+λ) − (G_L+G_R)²/(H_L+H_R+λ) ] − γ G = sum of slopes, H = sum of curvature. For log loss, each row adds g = p − y and h = p(1 − p).

Try this

  • Move λ from 0 to 1. The tiny leaf's push drops 61%, from 3.44 to 1.34. The large leaf's push drops only 13%. λ distrusts leaves with little evidence.
  • Keep λ at 1 and raise γ past 2.36. The fee now exceeds the gain, and the split is pruned.

Good atA strong, well-documented all-rounder for tabular data, with many control options.

Watch outIt has many settings. Its default growth is level by level, which you can change with grow_policy.

LIGHTGBM / 2017

LightGBM

Spend each split where it helps most, and round values into bins to go fast.

Picture a repair crew in a leaky building. Level-wise growth fixes every floor evenly before moving up. Leaf-wise growth sends the crew to the worst remaining leak, wherever it is.

I built this data with its detail concentrated in one corner, which favors leaf-wise growth. A gap this large isn't guaranteed on real data. Deep, lopsided trees can also memorize small datasets, so limit them with num_leaves, min_data_in_leaf and max_depth.

The speed trick: histograms

A classic tree tests a split at every distinct value. LightGBM first groups each column into bins, then only tests the boundaries between them. XGBoost's default hist method uses the same idea.

Split points to test, every value
Split points to test, with bins

This is a made-up, income-like column, and values above 1,400 aren't drawn. The boundaries crowd together where data is dense, so little detail is lost. LightGBM's default is 255 bins. Two more options cut the work further: GOSS keeps rows with large errors and samples the rest, and EFB bundles columns that are rarely non-zero at the same time.

Good atFast training and quick experiments, especially on large tables. Handles categories and missing values natively.

Watch outIt's easier to overfit on small datasets if the leaf count is too high.

CATBOOST / 2017

CatBoost

Never let a row see its own answer.

Trees need numbers, so a category like occupation is often replaced with the default rate of that occupation. That's called target encoding. The catch is that each row's own outcome is included in the rate it receives, which leaks the answer into the features.

CatBoost's fix is like marking exam papers in a random order, where each paper can only use results from papers marked before it.

Try this

  • Find the only customer in Occupation C. The plain mean gives 1.00, which is exactly their own outcome. A model would treat that as a perfect signal, and it would fail on new customers.
  • Step through and see that encodings change by position. Early rows have little history, so CatBoost trains across several random orders to even this out.
  • Ordered boosting applies the same rule to errors. It computes each row's error using models that haven't seen that row. You turn it on with boosting_type="Ordered".

Symmetric trees: one question per level

By default, every node on a level asks the same question. That limits each tree, which helps against overfitting, and makes predictions fast because the answers directly give the leaf number. Going right means yes.

Good atData with many categorical columns. Often performs well with little tuning.

Watch outTraining on CPU is often slower than LightGBM, so each experiment takes longer.

For your AIFUL model

Your competition is ranked by ROC-AUC, and overview.md lists 7 columns that are category codes: occupation, industry, employment type, insurance type, company size, business entity type and residence type. Training has about 68,500 rows, so all three modern libraries should train quickly enough to compare.

  1. Start with LightGBM and early stopping, for fast feedback on features.
  2. Add CatBoost and pass the 7 columns through cat_features. Its strength matches this data.
  3. Score both on the same 5 folds you've already been using, so the comparison is fair.
  4. Try a blend of the two, and keep it only if out-of-fold AUC improves. XGBoost is a good third member.

Skip AdaBoost as a main model. Your AUC near 0.65 suggests that much of the outcome can't be predicted from these columns, and that's the kind of noise that can pull AdaBoost off course. Also make sure category codes are declared as categorical. Otherwise a model treats occupation code 12 as “greater than” code 3.
